# Как машина учится на примерах. Обучение с учителем в действии
Машинное обучение (Machine Learning, ML) — это область искусственного интеллекта, которая позволяет компьютерам учиться на данных и делать прогнозы без явного программирования всех правил. Один из самых популярных подходов — **обучение с учителем**, когда у нас есть входные данные и правильные ответы (метки).
В этой статье мы рассмотрим несколько алгоритмов, ключевые концепции обучения и покажем пример на 1С: Элемент.
## Линейная регрессия

Линейная регрессия — это **алгоритм обучения с учителем**, который используется для прогнозирования **числовых значений**.

**Примеры:**
- Цена квартиры в зависимости от площади и района.
- Доход человека в зависимости от образования и опыта работы.
- Сумма покупок в интернет-магазине в зависимости от количества посещений сайта.

**Идея:** найти **линейную зависимость** между входными данными (признаками) и целевой переменной.

Формально:

$$
y=w1​⋅x1​+w2​⋅x2​+⋯+wn​⋅xn​+b
$$

- y — прогноз (целевое значение).
- x<sub>i​</sub> — признаки (например, площадь квартиры, количество комнат).
- w<sub>i</sub>— веса модели (коэффициенты, показывающие влияние каждого признака).
- b — смещение (bias), точка пересечения линии с осью Y.

#### Простейший случай: один признак

Если у нас только один признак x (например, площадь квартиры), формула упрощается:

$$
y=w⋅x+b
$$

Геометрически это **прямая линия** на графике, где:
- x — площадь
- y — цена квартиры
- w — наклон линии
- b — смещение

**Цель:** найти такие `w` и `b`, чтобы линия максимально точно проходила через точки данных.

#### Как модель учится

Чтобы определить `w` и `b`, используется **метод наименьших квадратов**:

1. Сначала считаем **ошибку для каждой точки** — разницу между реальной и предсказанной ценой:

$$
ei=yi​−(w⋅xi​+b)
$$

2. Далее минимизируем **сумму квадратов ошибок**:

$$
MSE = \frac{1}{N} \sum_{i=1}^{N} e_i^2 = \frac{1}{N} \sum_{i=1}^{N} (y_i - (w \cdot x_i + b))^2
$$
	- MSE (Mean Squared Error) — среднеквадратичная ошибка.
	- Меньше MSE → линия лучше подходит к данным.
3. Решение аналитически или через **градиентный спуск**:
	- Аналитическое решение (для одного признака):

$$
w = \frac{\sum (x_i - \bar{x}) (y_i - \bar{y})}{\sum (x_i - \bar{x})^2}, \quad b = \bar{y} - w \cdot \bar{x}
$$

- $\bar{x}, \bar{y}$ — средние значения признака и целевой переменной.

#### Пример на 1С:Элемент

```
// Описываем структуру данных, в которой будут храниться параметры недвижимости
// Каждая запись (экземпляр структуры) содержит два поля:
//  - Площадь (число, м²)
//  - Цена (число, тыс. руб.)
структура ДанныеЦенНедвижимости
    пер Площадь: Число
    пер Цена: Число
;

метод Скрипт()

    // 🔹 1. Исходные данные
    // Создаём массив объектов типа "ДанныеЦенНедвижимости".
    // Каждый элемент содержит площадь квартиры и её цену.
    // Эти данные имитируют историческую выборку, по которой мы "обучаем" модель.
    знч Данные = <ДанныеЦенНедвижимости>[
        новый ДанныеЦенНедвижимости(Площадь = 50, Цена = 3000),
        новый ДанныеЦенНедвижимости(Площадь = 60, Цена = 3800),
        новый ДанныеЦенНедвижимости(Площадь = 70, Цена = 4200),
        новый ДанныеЦенНедвижимости(Площадь = 80, Цена = 4600),
        новый ДанныеЦенНедвижимости(Площадь = 90, Цена = 5100)
    ]

    // 🔹 2. Делим выборку на обучающую и тестовую
    // Обучающая часть (Train) — первые 4 элемента.
    // По ним мы вычислим коэффициенты линейной модели.
    знч Train = Данные.ПодМассив(0,4) // первые 4 записи

    // Тестовая часть (Test) — последний элемент.
    // На нём проверим, насколько точен прогноз.
    знч Test = Данные.ПодМассив(4)  // последняя запись

    // 🔹 3. Подготовка переменных для вычисления коэффициентов
    // Здесь мы будем накапливать суммы, необходимые для аналитического расчёта w и b.
    пер СумX = 0    // сумма всех значений X (площадей)
    пер СумY = 0    // сумма всех значений Y (цен)
    пер СумXY = 0   // сумма произведений X*Y
    пер СумX2 = 0   // сумма квадратов X (X^2)

    // 🔹 4. Проходим по всем объектам обучающей выборки
    // Для каждого наблюдения добавляем его вклад в суммы.
    для Строка из Train 
        // Суммируем площадь
        СумX = СумX + Строка.Площадь

        // Суммируем цену
        СумY = СумY + Строка.Цена

        // Суммируем произведение X * Y (площадь * цена)
        // Это нужно для формулы вычисления коэффициента w.
        СумXY = СумXY + Строка.Площадь * Строка.Цена

        // Суммируем квадраты площадей (X^2)
        // Это используется в знаменателе при вычислении w.
        СумX2 = СумX2 + Строка.Площадь * Строка.Площадь
    ;

    // 🔹 5. Вычисляем количество наблюдений в обучающей выборке
    пер N = Train.Размер()

    // 🔹 6. Вычисляем коэффициенты линейной регрессии
    // Формулы основаны на методе наименьших квадратов:
    // w — наклон линии (показывает, насколько сильно изменяется цена при изменении площади)
    // b — смещение (значение цены при площади = 0)
    //
    // Формулы:
    // w = (N * ΣXY - ΣX * ΣY) / (N * ΣX² - (ΣX)²)
    // b = (ΣY - w * ΣX) / N
    пер w = (N * СумXY - СумX * СумY) / (N * СумX2 - СумX * СумX)
    пер b = (СумY - w * СумX) / N

    // 🔹 7. Проверка на тестовых данных
    // Теперь, когда мы знаем w и b, можно прогнозировать цену для новых площадей.
    для Строка из Test

        // Вычисляем прогноз по формуле:
        // прогноз = w * X + b
        пер Прогноз = w * Строка.Площадь + b

        // Выводим фактическую цену и предсказанную моделью.
        // Так можно визуально оценить точность прогноза.
        Консоль.Записать("Фактическая цена: " + Строка.Цена + ", Прогноз: " + Прогноз)
    ;

;
```

Результат

```
Фактическая цена: 5100, Прогноз: 5200
```
#### Почему линейная регрессия полезна

- Простая и интерпретируемая: легко понять влияние каждого признака.
- Быстро обучается даже на больших данных.
- Хороша для **первичного анализа данных** и прогнозирования.

#### Ограничения

- Линейная регрессия плохо работает, если **зависимость не линейная**.
- Чувствительна к выбросам.
- Иногда нужно использовать **регуляризацию**, чтобы избежать переобучения.

> [!NOTE] Вывод
> Линейная регрессия — это основа обучения с учителем и один из самых интуитивных алгоритмов в машинном обучении.  
> Её сила — в простоте и прозрачности:
> 
> - она показывает, **как именно** признаки влияют на результат;
> - позволяет **быстро построить прогнозы** и понять общие тенденции;
> - служит **отправной точкой** для изучения более сложных моделей.
> 
> Однако важно помнить, что линейная регрессия эффективна **только при линейных зависимостях**.  
> Если данные имеют нелинейную структуру, то лучше использовать другие методы — например, **деревья решений** или **нейронные сети**.
> 
> Таким образом, линейная регрессия — это не просто математическая формула, а **первый шаг в обучении машины понимать закономерности в данных**.


## Логистическая регрессия

Логистическая регрессия — это **линейная модель, которая предсказывает вероятность** принадлежности объекта к классу 1.  
Под капотом — обычная линейная комбинация признаков (веса × значения), но результат интерпретируется не как число, а как вероятность после **сжатия сигмоидой**.  
Если вероятность выше порога (обычно 0.5) — объект относят к положительному классу.
### Как работает обучение

Модель проходит по данным с известными метками (0/1), делает прогнозы и оценивает ошибку с помощью **логарифмической функции потерь**.  
Эта функция особенно наказывает «уверенные ошибки» — когда модель почти уверена, но ошибается.  
Далее веса корректируются с помощью **градиентного спуска**: шаг за шагом минимизируется ошибка на всей выборке.

Итог — набор весов, отражающих вклад каждого признака в вероятность положительного исхода.

#### Интерпретация и контроль

- **Положительный вес** — признак повышает вероятность класса 1.
- **Отрицательный вес** — понижает.
- **Нулевой или близкий к нулю** — не влияет.

Чтобы избежать переобучения, добавляют **регуляризацию** (L1 — отбор признаков, L2 — сглаживание весов).  
Перед обучением обычно нормализуют данные — это ускоряет и стабилизирует обучение.

#### Когда использовать

Логистическая регрессия — это отправная точка для решения задач бинарной классификации.
Она:
- обучается быстро;
- легко интерпретируется;
- даёт стабильные результаты при линейных зависимостях.

#### Когда не подойдёт

- Классы разделяются **нелинейно** (граница «прямая»);
- Признаки сильно коррелированы;
- Сильный **дисбаланс классов** без корректировки порога.

#### Пример на 1С:Элемент
```
структура ДанныеКлиентов
    пер СуммаЗадолженности: Число   // сумма долга клиента
    пер КлиентПостоянный: Число    // 1 если клиент постоянный, 0 если нет
    пер ДнейДоОплаты: Число        // сколько дней осталось до срока оплаты
    пер Оплатил: Число             // целевая переменная: 1 если оплатил вовремя, 0 если просрочка
;

метод Скрипт()
    // Запуск основного метода логистической регрессии
    ЛогистическаяРегрессия()    
;

метод ЛогистическаяРегрессия()

    // === 1. Данные (тренировочные) ===
    // Здесь создаём небольшой набор данных для обучения модели
    знч Данные = новый Массив<ДанныеКлиентов>()
    Данные.Добавить(новый ДанныеКлиентов(2000, 1, 3, 1))
    Данные.Добавить(новый ДанныеКлиентов(5000, 0, 10, 0))
    Данные.Добавить(новый ДанныеКлиентов(1500, 1, 2, 1))
    Данные.Добавить(новый ДанныеКлиентов(7000, 0, 12, 0))
    Данные.Добавить(новый ДанныеКлиентов(3000, 1, 5, 1))
    Данные.Добавить(новый ДанныеКлиентов(4000, 0, 7, 0))

    // === 2. Начальные веса ===
    // Все веса и смещение начинаются с нуля
    пер Смещение = 0       // b0
    пер ВесСумма = 0       // вес для признака "СуммаЗадолженности"
    пер ВесПостоянный = 0  // вес для признака "КлиентПостоянный"
    пер ВесДней = 0        // вес для признака "ДнейДоОплаты"

    // === 3. Параметры обучения ===
    пер Альфа = 0.01 // скорость обучения (увеличена для быстрого сходимости)
    пер Эпохи = 20000 // количество проходов по всему набору данных

    // Максимальные значения признаков для нормализации
    // Нормализация важна, чтобы признаки с большими числами не доминировали
    пер maxСумма = 7000
    пер maxДней = 12

    // Цикл обучения
    для Эпоха = 1 по Эпохи

        // === Накопление градиентов для одного шага градиентного спуска ===
        пер ГрСмещение = 0
        пер ГрСумма = 0
        пер ГрПостоянный = 0
        пер ГрДней = 0

        // Проходим по каждой записи тренировочных данных
        для Запись из Данные

            // Нормализуем признаки, чтобы все были в диапазоне 0..1
            пер суммаН = Запись.СуммаЗадолженности / maxСумма
            пер дниН = Запись.ДнейДоОплаты / maxДней

            // Считаем линейную комбинацию признаков (z)
            пер Z = Смещение + ВесСумма * суммаН + ВесПостоянный * Запись.КлиентПостоянный + ВесДней * дниН

            // Применяем сигмоидную функцию для получения вероятности P
            пер P = 1 / (1 + Exp(-Z))

            // Ошибка = разница между предсказанной вероятностью и фактическим значением
            пер Ошибка = P - Запись.Оплатил

            // Накопление градиентов для обновления весов
            ГрСмещение = ГрСмещение + Ошибка
            ГрСумма = ГрСумма + Ошибка * суммаН
            ГрПостоянный = ГрПостоянный + Ошибка * Запись.КлиентПостоянный
            ГрДней = ГрДней + Ошибка * дниН

        ;

        // === Обновляем веса и смещение ===
        пер N = Данные.Размер() // количество записей
        Смещение = Смещение - Альфа * (ГрСмещение / N)
        ВесСумма = ВесСумма - Альфа * (ГрСумма / N)
        ВесПостоянный = ВесПостоянный - Альфа * (ГрПостоянный / N)
        ВесДней = ВесДней - Альфа * (ГрДней / N)

    ;

    // === 4. Результаты обучения ===
    Консоль.Записать("Обученные веса:")
    Консоль.Записать("Смещение: " + Смещение.Округлить(10))
    Консоль.Записать("ВесСумма: " + ВесСумма.Округлить(10))
    Консоль.Записать("ВесПостоянный: " + ВесПостоянный.Округлить(10))
    Консоль.Записать("ВесДней: " + ВесДней.Округлить(10))

    // === 5. Проверим новую заявку ===
    знч новыйСчет = новый ДанныеКлиентов(3500, 1, 10)

    // нормализация новых данных перед предсказанием
    пер суммаН = новыйСчет.СуммаЗадолженности / maxСумма
    пер дниН = новыйСчет.ДнейДоОплаты / maxДней

    // Предсказание вероятности оплаты
    пер Z = Смещение + ВесСумма * суммаН + ВесПостоянный * новыйСчет.КлиентПостоянный + ВесДней * дниН
    пер Вероятность = 1 / (1 + Exp(-Z))

    // Вывод результата
    Консоль.Записать("Вероятность оплаты вовремя: ${Вероятность * 100} %")
    если Вероятность > 0.5 
        Консоль.Записать("Прогноз: клиент, скорее всего, оплатит вовремя.")
    иначе
        Консоль.Записать("Прогноз: есть риск просрочки.")
    ;

;

```
### Как это работает

- Код проходит по всем записям **много раз (эпохи)**,  
    постепенно корректируя веса, чтобы уменьшить ошибку.
- После обучения — веса начинают отражать влияние каждого признака:
    - `ВесСумма < 0` → чем больше сумма, тем меньше шанс вовремя оплатить
    - `ВесПостоянный > 0` → постоянные клиенты чаще платят вовремя
    - `ВесДней < 0` → чем больше дней, тем выше риск просрочки
      

> [!NOTE] Вывод
> 
> Логистическая регрессия — простой и прозрачный инструмент для бинарной классификации. Она позволяет **понять вклад каждого признака**, быстро обучается и даёт вероятностные прогнозы, что удобно для принятия решений.
> 
> Однако стоит помнить её ограничения: модель **не справится с сильной нелинейностью, высокой корреляцией признаков или серьёзным дисбалансом классов** без дополнительной обработки данных.
> 
> В итоге, логистическая регрессия — отличная отправная точка, которая часто используется как базовая модель перед переходом к более сложным алгоритмам.


## Деревья решений

**Дерево решений** — это один из самых интуитивных и наглядных алгоритмов машинного обучения.  
Оно имитирует процесс человеческого рассуждения: модель принимает решения, последовательно отвечая на простые вопросы вроде  
_«Возраст больше 30?»_ или _«Доход выше среднего?»_.

Каждый такой вопрос делит данные на группы, а в конце каждой ветви (в «листе») дерево выдаёт итоговое предсказание — например, класс 0 или 1, или конкретное числовое значение.

### Как работает обучение

Алгоритм строит дерево **сверху вниз**, начиная с корня — самого первого вопроса.  
На каждом шаге выбирается тот признак и то пороговое значение, которые **лучше всего разделяют данные**.

Например, если мы хотим предсказать, купит ли человек товар, модель попробует разные признаки:

- возраст,
- доход,
- наличие скидки,
- количество предыдущих покупок —

и выберет тот, по которому группы «купил / не купил» окажутся наиболее однородными.

Чтобы измерить, насколько «чистыми» стали группы, используют **метрики неоднородности**:

- **Gini impurity (индекс Джини)** — для классификации;
- **Entropy (энтропия)** — тоже для классификации, похожа по смыслу;
- **MSE (среднеквадратичная ошибка)** — для регрессии.

Далее процесс повторяется для каждой ветви — пока дерево не станет слишком глубоким или пока внутри ветви не останется слишком мало данных.

### Пример

Представим, что у нас есть данные о клиентах, и мы хотим предсказать, купит ли человек подписку.
Дерево может построить логику примерно так:

`Если возраст > 30:     Если доход > 100 000 → Купит     Иначе → Не купит Иначе:     Если есть скидка → Купит     Иначе → Не купит`

Это и есть готовая модель — простая, но читаемая даже без математики.

    пер Доход: Число
    пер КредитнаяИстория: Число // 1 = хорошая, 0 = плохая
    пер Одобрен: Число? // 1 = да, 0 = нет (целевой признак, иногда неизвестен)

// ------------------------------------------------------------
// Основная точка входа
// Здесь создаются тренировочные данные, вызываются тесты и вывод дерева
// ------------------------------------------------------------
метод Скрипт()
    
    // === 1. Тренировочные данные ===
    // Мы создаём набор клиентов, по которым уже известен результат (одобрен/отказ)
    // Это «обучающая выборка» — на ней строится логика дерева решений
    пер Данные = новый Массив<ДанныеКлиента>()
    Данные.Добавить(новый ДанныеКлиента(25, 30000, 1, 1))  // одобрен
    Данные.Добавить(новый ДанныеКлиента(45, 25000, 0, 0))  // отказано
    Данные.Добавить(новый ДанныеКлиента(35, 50000, 1, 1))  // одобрен
    Данные.Добавить(новый ДанныеКлиента(28, 20000, 0, 0))  // отказано
    Данные.Добавить(новый ДанныеКлиента(40, 45000, 1, 1))  // одобрен
    Данные.Добавить(новый ДанныеКлиента(22, 18000, 1, 0))  // отказано (исключение — обучает модель гибкости)
    
    Консоль.Записать("=== ДЕРЕВО РЕШЕНИЙ ДЛЯ КРЕДИТА ===")
    
    // === 2. Проверяем работу дерева на новых данных ===
    // Создаём клиентов, для которых нужно сделать прогноз
    пер ТестКлиент1 = новый ДанныеКлиента(30, 35000, 1, Неопределено)
    пер ТестКлиент2 = новый ДанныеКлиента(50, 15000, 0, Неопределено)
    
    // Применяем дерево решений
    Консоль.Записать("Клиент 1 (30 лет, доход 35к, история хорошая):")
    пер Решение1 = ПринятьРешение(ТестКлиент1)
    Консоль.Записать("Решение: " + Решение1)
    
    Консоль.Записать("Клиент 2 (50 лет, доход 15к, история плохая):")
    пер Решение2 = ПринятьРешение(ТестКлиент2)
    Консоль.Записать("Решение: " + Решение2)
    
    // === 3. Показать дерево в виде текста ===
    // Это визуализация логики, по которой принимает решения модель
    ПоказатьДеревоРешений()
    
;

// ------------------------------------------------------------
// Функция принятия решения (модель дерева решений)
// ------------------------------------------------------------
метод ПринятьРешение(Клиент: ДанныеКлиента): Строка
    
    // Первый уровень дерева: проверяем кредитную историю
    если Клиент.КредитнаяИстория == 1
        // Второй уровень: проверяем доход
        если Клиент.Доход >= 25000 
            // Хорошая история + нормальный доход → кредит одобрен
            возврат "Кредит ОДОБРЕН ✓ (хорошая история + достаточный доход)"
        иначе
            // Хорошая история, но низкий доход → отказ
            возврат "Кредит ОТКАЗАНО ✗ (хорошая история, но низкий доход)"
        ;
    иначе
        // История плохая → проверяем компенсирующие признаки
        если Клиент.Возраст >= 30 
            // Старший возраст может говорить о стабильности
            если Клиент.Доход >= 40000 
                возврат "Кредит ОДОБРЕН ✓ (возраст + высокий доход компенсируют историю)"
            иначе
                возврат "Кредит ОТКАЗАНО ✗ (плохая история + недостаточный доход)"
            ;
        иначе
            возврат "Кредит ОТКАЗАНО ✗ (плохая история + молодой возраст)"
        ;
    ;
    
;

// ------------------------------------------------------------
// Печать визуализации дерева решений в консоль
// ------------------------------------------------------------
метод ПоказатьДеревоРешений()

    Консоль.Записать("=== СТРУКТУРА ДЕРЕВА РЕШЕНИЙ ===")

    Консоль.Записать("    │   └── НЕТ → ОТКАЗАНО ✗")
    Консоль.Записать("    └── НЕТ → ОТКАЗАНО ✗")
    
;

// Проверка точности дерева на обучающих данных
// (сколько решений совпадает с ожидаемыми)
// ------------------------------------------------------------
метод ПроверитьТочность()
    
    пер Данные = ПолучитьТренировочныеДанные()
    пер ПравильноПрогнозировано = 0
    
    для Клиент из Данные 
        пер Решение = ПринятьРешение(Клиент)
        // Преобразуем ожидаемый результат в текст для сравнения
        пер ОжидаемыйРезультат = (Клиент.Одобрен==1 ? "ОДОБРЕН": "ОТКАЗАНО")

            ПравильноПрогнозировано = ПравильноПрогнозировано + 1
        ;
    ;
    
    // Считаем процент правильных ответов
    пер Точность = ПравильноПрогнозировано / Данные.Размер() * 100
    Консоль.Записать("Точность на тренировочных данных: " + Точность + "%")
    
;

// (повторяет данные из начала, чтобы использовать в проверке точности)
// ------------------------------------------------------------
метод ПолучитьТренировочныеДанные(): Массив<ДанныеКлиента>
    пер Данные = новый Массив<ДанныеКлиента>()

    возврат Данные

### Интерпретация и плюсы

Главное достоинство деревьев решений — **понятность**.  
Модель можно легко визуализировать, объяснить заказчику или встроить в бизнес-логику:  
всегда видно, **почему** был принят тот или иной выбор.
Другие преимущества:
- Умеют работать и с **числовыми**, и с **категориальными** данными;
- Естественно поддерживают **нелинейные зависимости** — дерево может построить сложные разветвлённые границы между классами;
- Не требуют масштабирования признаков (нормализации).

### Недостатки

Однако простота дерева имеет оборотную сторону:

- Оно легко **переобучается**, если растёт слишком глубоким и начинает запоминать конкретные примеры;
- Результат может сильно зависеть от случайных колебаний в данных — чуть изменили обучающую выборку, и структура дерева может стать совсем другой;
- На больших данных точность может быть ниже, чем у ансамблей (например, случайного леса).

Чтобы избежать переобучения, дерево можно **ограничить по глубине**, задать минимальное число примеров в ветви или применить **обрезку (pruning)** — удаление малозначимых ветвей после обучения.

### Когда использовать

Деревья решений хорошо подходят, если:

- нужно получить **интерпретируемую** модель;
- данные содержат **разные типы признаков**;
- зависимость между признаками **не линейна**;
- вы хотите быстро построить базовую модель и понять структуру данных.

> [!NOTE] Вывод
> 
> Дерево решений — это модель, которая учится **разделять пространство данных на зоны решений** при помощи серии простых условий.  
> Оно сочетает в себе наглядность, гибкость и скорость обучения, поэтому часто используется как первая ступень к более мощным ансамблевым методам — например, **случайным лесам** и **градиентному бустингу**.

## Заключение

Обучение с учителем — это сердце машинного обучения. Мы показываем машине примеры, объясняем, где правильный ответ, и постепенно она начинает **замечать закономерности**, которые человек часто не видит.

Сначала мы разобрали, как **линейная регрессия** учится находить числовые зависимости.  
Потом увидели, как **логистическая регрессия** превращает эти зависимости в вероятности и помогает решать задачи «да/нет».  
А затем перешли к **деревьям решений**, где модель учится рассуждать почти как человек — задавая простые, но точные вопросы.

Все эти методы разные, но цель одна: **научить машину делать выводы на основе опыта**.  
Так, шаг за шагом, компьютер превращается из простого вычислителя в систему, способную понимать данные и принимать решения.

И это только начало.  
В следующих разделах можно будет заглянуть дальше — в **ансамбли моделей, нейронные сети и обучение без учителя**, где машина учится уже **сама**, без подсказок.
